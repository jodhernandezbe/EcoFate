## Ranked proposals

1. **Absent values are loud and repeated** (App first load, Overview summary empty and ready;
   H1 H3 H7).
   - Observation: 14 slots read "not reported" in `text-fg`, five of them at the large
     value size, so the empty overview is a wall of the same phrase and the largest text on
     screen says nothing (`app-first-load-light`, `overview-fullscreen-light`). DESIGN.md says an
     absent value sits in `text-fg2`. Separately, an unknown status reads "Not computed" on the
     risk pills but "Not reported" on the worker pills (`components/ui/StatusPill.tsx:11`,
     `components/ui/TierPill.tsx:11`).
   - Proposal: render absent values in `text-fg2` at body size (not the large value size), and
     make `TierPill` say "Not computed" like `StatusPill`.
   - Design document impact: Required states, Absent value row: "at body size, never the large
     value size"; Copy: one word for unknown status.
   - Effort: S. Value: high (every empty and partial surface, first impression).

2. **Overview rows still stretch around empty cards** (Overview summary, H2 H10).
   - Observation: the first-row fix works, but other rows still use
     `auto-rows-[minmax(max-content,1fr)]` (`features/overview/EpaOverviewRibbon.tsx:24`), so
     "Population not reported yet." and "Weather not reported yet." sit in cards 150 to 300 px
     tall (`overview-fullscreen-light`, `ribbon-ready-dark`). This breaks the document's
     "empty sections take their content height" rule. In the default split the panel shows about
     one and a half cards and clips mid-card with no cue that it scrolls (`app-first-load-*`,
     `app-narrow-dark`).
   - Proposal: use `auto` rows for every row that holds an empty card (apply the existing
     first-row rule per row); add a bottom fade or a visible scrollbar on the clipped panel.
   - Design document impact: none (rule exists); add "a clipped panel shows that it scrolls".
   - Effort: S to M. Value: high (three layouts).

3. **Settings drawer is a tall box with a thin top** (Settings, H1 H2).
   - Observation: the drawer fills about 60 % of the window height while its content is two rows
     in the top 140 px (`settings-drawer-light`).
   - Proposal: size the drawer to its content (`BottomDrawer` already has `max-h-full`); open
     the first section whose key is missing.
   - Design document impact: none.
   - Effort: S. Value: medium.

4. **Type and radius off the documented ladder** (Shell, Exposure chain, Chat, Monitoring, Map;
   H3).
   - Observation, from the static checks: `text-[10px]` on chain node badges and values
     (`features/exposure-chain/ChainNode.tsx:51,57`) and on the expanded rail badge with
     `rounded-md` and uppercase (`components/layout/LeftNavRail.tsx:76`); edge labels in
     `both-lanes-wide-light` are smaller still; `rounded-3xl` on the composer
     (`features/chat/ChatComposer.tsx:38`); `rounded-md` on three links and buttons;
     uppercase sub-labels outside panel and card titles (`FacilityHoverCard.tsx:75,83,180,186`,
     `ScenarioView.tsx:55,89`, `MessageStream.tsx:28`, `MonitoringView.tsx:117`,
     `SessionsTable.tsx:47`); literal hex fallbacks that copy token values
     (`features/map/layers.ts:32-37`).
   - Proposal: one sweep: raise chain text to the 11 px micro step, move to `rounded-lg` /
     `rounded-2xl`, and keep uppercase to `PanelHeader` and `CardFrame`; drop the hex fallbacks
     or read them from one place. Decide whether table column heads and the rail "planned"
     badge are titles (then document it) or sentence case.
   - Design document impact: Type table gets a row for table column heads if kept uppercase;
     remove the "Known drift" `rounded-md` line when done.
   - Effort: M (touches ten files, mechanical). Value: medium (consistency, legibility of the
     signature canvas).

5. **Composer focus ring is a square inside a rounded pill** (Chat, H3 H6).
   - Observation: with text entered, `chat-composer-filled-dark` shows a rectangular accent
     outline inside the rounded composer, clipped to the input box instead of following the pill.
   - Proposal: move the focus style to the composer container (`focus-within:`), remove the
     outline from the inner field, keep the 2 px accent ring with offset.
   - Design document impact: none.
   - Effort: S. Value: medium (the most used control).

6. **Failed sessions give no reason** (Monitoring, H4 H7 H10).
   - Observation: five rows read "Failed" with "not reported" cost and nothing else
     (`monitoring-light`); the answer is only in the session detail, which was not opened.
   - Proposal: add a short reason beside the status when Logfire returned one ("no model
     response", the error class in words), else "reason not reported".
   - Design document impact: none.
   - Effort: M (needs the API field checked first). Value: medium.

7. **Disabled chat-header buttons say nothing** (Chat, H4 H6).
   - Observation: the "Clear chat" button is dimmed and `pointer-events-none` while disabled
     (`features/chat/ClearChatButton.tsx:16-18`), so its title never shows and no reason is
     given; the rail entries already carry a reason through `blocked`.
   - Proposal: reuse the rail's pattern: a reason string, `aria-description`, and let the
     tooltip show.
   - Design document impact: none (rule exists).
   - Effort: S. Value: low to medium.

8. **Brand name three times on first load, and a bright attribution chip in dark** (App first
   load, Map; H1 H3).
   - Observation: "EcoFate" appears in the rail, the chat header and the welcome block
     (`app-first-load-light`); the MapLibre attribution stays a white pill in dark
     (`map-fullscreen-dark`).
   - Proposal: drop the title from the chat header or the welcome block; style the attribution
     control with `--surface-solid` and `--fg-2`.
   - Design document impact: none.
   - Effort: S. Value: low.
